# Keyboop для Windows

Порт голосового ввода Keyboop на Windows: зажал хоткей, продиктовал, отпустил — текст появился
в активном окне, **со знаками препинания**, целиком на твоём компьютере.

Плюс главная функция оригинала: набрал `ghbdtn` вместо `привет` — Keyboop это молча расколдует
и переключит язык.

---

## Что уже есть

- **Исправление раскладки.** На границе слова детектор решает, набрано ли слово не в той
  раскладке, и если да — перепечатывает его и переключает язык.
- **Диктовка по хоткею.** По умолчанию удерживать `F9`; есть режим «переключать».
- **Автоматическая пунктуация.** Тот самый механизм, ради которого порт и затевался — подробно
  ниже.
- **Ничего не уходит в сеть.** Распознавание идёт локально через whisper.cpp.
- **Буфер обмена не трогаем.** Текст печатается через `SendInput` с флагом Unicode, минуя
  раскладку. Твой скопированный текст остаётся на месте — это краеугольный принцип Keyboop.
- **Фильтр фраз-призраков.** whisper на тишине любит дописывать «Продолжение следует» и
  «Субтитры создавал…» — они отсекаются, не доходя до поля ввода.
- **Отмена по `Escape`** во время записи.

## Как работает автоматическая пунктуация

Это не постобработка и не отдельная модель. whisper авторегрессионный: он продолжает то, что ему
дали началом. На холодном декоде он примерно **в трети случаев** залипает в «режим без пунктуации»
и выдаёт всю реплику сплошняком. В телеметрии macOS-версии у всех таких случаев аудио было
чистым, а длина роли не играла — сплошняк приходил и на 526 символов.

Лечится показом примера нужного стиля. Перед распознаванием модели подаётся затравка —
натуральная фраза со всеми ключевыми знаками:

> Привет! Как дела? Сегодня хорошая погода, но, кажется, скоро пойдёт дождь. Ну что ж, подождём —
> время ещё есть.

Плюс `carry_initial_prompt`, чтобы на диктовке длиннее 30 секунд (это уже несколько окон декодера)
знаки не пропадали начиная со второго окна.

Правила, проверенные на живых пользователях macOS-версии и перенесённые как есть:

| Правило | Почему |
|---|---|
| Затравка — натуральная фраза, а не «мешок знаков» `., ? !` | Короткие и атипичные промпты умеют искажать слова |
| Затравка под язык речи | Русская затравка на английской речи тянет вывод к русскому |
| Без `«` `»` `:` `;` | Модель принимает ёлочки за прямую речь и заворачивает в них не-речь |
| Срезаем эхо затравки с начала расшифровки | На почти-тишине модель иногда «продолжает» саму затравку |

Всё это живёт в [`PunctuationPrompt`](src/Keyboop.Core/Speech/PunctuationPrompt.cs) и
[`WhisperDecodeProfile`](src/Keyboop.Core/Speech/WhisperDecodeProfile.cs) — и покрыто тестами.

## Сборка

Нужен [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).

```bash
dotnet test                                    # логика ядра — идёт на любой ОС
dotnet build src/Keyboop.Windows -c Release    # само приложение — нужен Windows
```

Модель скачивается отдельно (файл `ggml-*.bin` с
[Hugging Face](https://huggingface.co/ggerganov/whisper.cpp/tree/main)) и указывается в меню трея →
**Выбрать модель…**. Разумный старт — `ggml-large-v3-turbo-q5_0.bin` (~550 МБ): заметно точнее
мелких моделей на русском и всё ещё быстрый.

Для видеокарты замени в `Keyboop.Windows.csproj` пакет `Whisper.net.Runtime` на
`Whisper.net.Runtime.Cuda` или `.Vulkan` — код менять не нужно.

## Устройство

```
src/Keyboop.Core/      ← без зависимостей от ОС, тестируется где угодно
   Speech/             затравка, профиль декодирования, фильтр призраков, оформление вывода
   Audio/              приведение к 16 кГц моно, гейт «тишина / слишком коротко»
   Layout/             детектор раскладки, таблица клавиш, словари, буфер набора,
                       предохранитель от резонанса, списки исключений
src/Keyboop.Windows/   ← всё, что умеет только Windows
   Interop/            перехватчик клавиатуры, вставка текста, переключение раскладки,
                       декодирование клавиш через ToUnicodeEx
   Audio/              захват микрофона (WASAPI)
   Speech/             адаптер Whisper.net, применяющий профиль из ядра
   LayoutEngine.cs     связывает буфер, детектор и замену текста
tests/                 ← тесты ядра
```

Граница проведена намеренно: в `Keyboop.Core` нет ни одного вызова Windows, поэтому весь
детектор проверяется тестами на любой машине — включая Linux в CI. Языковые данные не копируются
в репозиторий, а подключаются из `Sources/Keyboop/Resources` напрямую: формат тот же, что в
macOS-версии.

## Как работает исправление раскладки

Детектор перенесён из macOS-версии целиком, вместе со словарями, триграммами и всеми
курируемыми списками — их там собирали по реальным промахам, и менять состав без такого же
замера нельзя. Каскад решений: отсев → форс-списки → словарь → триграммная статистика.

Главное правило — **strict-gate**: слово, валидное в языке, на котором оно набрано, не
переключается никогда, даже если его раскладочная пара тоже валидное слово. Английское `her`
не должно превращаться в «рук». Переключаем только кашу.

Вставка замены идёт **одним пакетом** `SendInput`: система вставляет его в очередь атомарно,
поэтому реальное нажатие человека физически не может лечь между нашими `Backspace` и
перепечаткой. В macOS-версии ровно эта гонка рождала «GПривет» — здесь такого класса ошибок
нет по построению.

Переключение языка идёт через `WM_INPUTLANGCHANGEREQUEST` активному окну. `ActivateKeyboardLayout`
здесь не годится: он меняет раскладку только вызывающему потоку, а мы фоновое приложение.

## Чего ждать не стоит

- **Правки на лету (посреди слова) пока нет** — исправляем на границе слова.
- **Сниппетов и группового переключения фразы пока нет.**
- **Движка Parakeet не будет в прежнем виде.** В macOS-версии он работает на Apple Neural Engine,
  которого на Windows не существует. Аналог (Parakeet через ONNX Runtime) — отдельная задача.
- **В окнах с правами администратора хоткей не сработает.** Приложение сознательно запускается без
  повышения прав: программа, которая постоянно висит в трее и читает каждое нажатие клавиши,
  не должна иметь права администратора. Подробнее — в [`app.manifest`](src/Keyboop.Windows/app.manifest).
